2.1Data transmission

Data travels in packets

A file sent across the internet is chopped into small packets, each labelled with where it is going. Routers pass each packet on separately, and the receiver puts them back together.

1

Understand

Three sections and a checklist

2.1.1

Data packets

Data sent over a network is broken into packets — small units of data. Each packet has three parts:

PartContains
Packet headerthe destination IP address, the originator’s (sender’s) IP address, and the packet number
Payloadthe actual data being sent
Trailera way of identifying the end of the packet, and an error check (e.g. a checksum or CRC)

Packet switching

  1. the data is broken into packets
  2. each packet may take a different route — each router reads the destination address and forwards the packet along the best available path
  3. packets may arrive out of order
  4. the receiver reorders them using the packet numbers; any missing packets are requested again

Benefits: no single path is tied up; if a link fails or is busy, packets go another way. Drawback: packets can be delayed or lost and must be reassembled.

2.1.2

Methods of data transmission

MethodHowAdvantagesDisadvantages
Serialbits sent one at a time down a single wirereliable over long distances; bits arrive in order; cheaper cableslower than parallel
Parallelseveral bits sent at the same time down several wiresfaster over short distancesbits can arrive skewed (out of sync) over long distances; more expensive

Half-duplexboth ways, but one direction at a timetwo-way with one channelslower — e.g. walkie-talkie
Full-duplexboth ways at the same timefastest two-wayneeds more channels — e.g. phone call, broadband

Exam questions combine them: “serial half-duplex”, “parallel simplex” and so on.

2.2Data transmission

Did it arrive exactly as sent?

Interference can flip a 1 into a 0 on the way. Parity bits, checksums, echo checks and check digits all add a little extra data so mistakes can be spotted — and the data sent again.

1

Understand

Three sections and a checklist

2.2.1

Parity check

  • errors happen during transmission because of interference: data can be lost, gained or changed
  • sender and receiver agree on odd or even parity
  • one bit of each byte — the parity bit — is set so that the byte has an odd (or even) number of 1s
  • the receiver counts the 1s; if the count is wrong, an error has occurred
  • a parity block adds a parity byte (a parity bit for each column too), so the receiver can find which bit is wrong — where the faulty row and column cross

Limit If two bits flip (or any even number), the count stays odd/even and the error is not detected.

2.2.2

Checksum, echo check and ARQ

MethodHow it works
Checksumthe sender calculates a value from the data using an agreed algorithm and sends it with the data; the receiver recalculates it — if the values differ, an error occurred and the data is requested again
Echo checkthe receiver sends a copy of the data back to the sender, which compares it with the original; any difference means an error and the data is resent (but the error may have happened on the way back)
Automatic repeat query (ARQ)the receiver checks the data with an error-detection method, then sends a positive acknowledgement, or a negative one to ask for it again; if the sender gets no acknowledgement before a timeout, it resends automatically
2.2.3

Check digits

  • a check digit is a final digit calculated from all the other digits of a code, such as an ISBN or a product barcode
  • it detects data entry errors: a digit typed wrongly, two digits swapped (transposition), digits missed out or added
  • the computer recalculates the check digit from the entered digits; if it does not match, the number is rejected

ISBN-13: multiply digits alternately by 1 and 3 · add · MOD 10 · check digit = 10 − remainder (10 → 0)

2.3Data transmission

Scramble it so only the right person can read it

Encryption doesn’t stop data being intercepted — it makes intercepted data useless. Only someone with the right key can turn the ciphertext back into plaintext.

1

Understand

Two sections and a checklist

2.3.1

What is encryption?

  • encryption scrambles data using an algorithm and a key, so that if it is intercepted it cannot be understood
  • the original data is the plaintext; the scrambled data is the ciphertext
  • encryption does not stop data being intercepted or deleted — it stops it being understood
2.3.2

Symmetric and asymmetric encryption

SymmetricAsymmetric
Keysone key — the same key encrypts and decryptsa public key and a private key that work as a pair
Howsender and receiver must both have the keythe receiver publishes their public key; senders encrypt with it; only the receiver’s private key can decrypt
Problemthe key must be sent to the receiver — if it is intercepted, the data can be readslower; but the private key never has to be sent
