4.1Software

Layers of software between you and the hardware

Applications do the jobs you want. The operating system sits underneath, managing the hardware so applications don’t have to — and it responds instantly when a device interrupts.

1

Four sections and a checklist

4.1.1

System software and application software

System softwareApplication software
Purposeprovides the services the computer needs to run; manages hardware and runs applicationslets the user carry out a task
Examplesoperating systems; utility software such as anti-virus, firewalls, defragmentation, backup, compression, disk formattingword processors, spreadsheets, web browsers, games, photo editors
4.1.2

The operating system

The OS manages the computer’s resources. Its functions include:

  • managing files — creating, naming, saving, moving and deleting files and folders
  • handling interrupts
  • providing an interface (GUI or command line) between user and computer
  • managing peripherals and drivers — sending and receiving data to and from devices
  • managing memory — allocating RAM to programs, moving data to and from virtual memory
  • managing multitasking — sharing processor time between programs
  • providing a platform for running applications
  • providing system security — user accounts, passwords, access rights
  • managing user accounts
4.1.3

Hardware, firmware and the operating system

  • applications run on the operating system, which runs on the hardware
  • firmware is software stored in ROM that provides low-level control of the hardware
  • the bootloader (firmware) runs when the computer is switched on, checks the hardware and loads the operating system into RAM
4.1.4

Interrupts

  • an interrupt is a signal sent to the processor to get its attention
  • hardware interrupts: a key pressed, the mouse moved, a printer out of paper, a device disconnected
  • software interrupts: a division by zero, two programs trying to use the same memory, a program requesting a service
  • interrupts have priorities; a higher-priority interrupt is handled first
  1. the interrupt is placed in a queue; at the end of the current fetch–decode–execute cycle the CPU checks for interrupts
  2. if there is one with a higher priority than the current task, the CPU saves the state (register contents) of the current task
  3. it runs the interrupt service routine (ISR) that handles that interrupt
  4. it restores the saved state and continues the original task

4.2Software

From code you can read to code the CPU can run

Programmers write in languages close to English. The CPU only understands machine code. Translators — compilers, interpreters and assemblers — bridge the gap.

1

Understand

Four sections and a checklist

4.2.1

High-level and low-level languages

High-level (Python, Java, C#)Low-level (assembly, machine code)
Reads likeEnglish and maths — easier to read, write, understand and debugmnemonics or binary — hard for humans
Hardwareportable: runs on different CPUs after translationwritten for one particular CPU’s instruction set
Controlone statement may become many machine instructionsdirect control of hardware and memory; can be very efficient and fast
Used formost applicationsdevice drivers, embedded systems, code that must be small and fast
4.2.2

Assembly language and assemblers

  • assembly language uses mnemonics (e.g. LDA, ADD, STO) — each usually stands for one machine code instruction
  • it must be translated into machine code by an assembler
  • programmers use it for direct control of the hardware, to make use of special CPU instructions, and to write code that runs quickly in little memory
4.2.3

Compilers and interpreters

CompilerInterpreter
Howtranslates the whole program at once into machine codetranslates and executes one line at a time
Outputan executable file that can be run without the compilerno executable; the interpreter is needed every time

Best fordistributing finished programs (source code stays private)developing and testing programs
4.2.4

Integrated development environments (IDEs)

An IDE is software that provides tools to help write and test programs:

  • code editor — with prettyprint (colour coding), auto-indentation, auto-completion and line numbers
  • run-time environment — to run the program
  • translator — a built-in compiler and/or interpreter
  • error diagnostics — highlights errors and suggests fixes
  • debugging tools — breakpoints, stepping through the code line by line, and watching variable values
