8.1Programming

The building blocks of every program

Every program, in every language, is built from the same few ideas: store values in variables, take input, make decisions, repeat, and split the work into named subroutines.

8.1.1

Variables, constants and data types

  • a variable is a named memory location whose value can change while the program runs
  • a constant is a named value that does not change (e.g. VAT rate, π) — makes the code easier to read and to update in one place

8.1.2

Input, output and sequence

  • INPUT takes data from the user; OUTPUT displays data
  • sequence: statements run one after another, in order
OUTPUT "Enter your name"
INPUT Name
OUTPUT "Hello ", Name
8.1.3

Selection: IF and CASE

IF Mark >= 70 THEN
   OUTPUT "A"
ELSE
   IF Mark >= 50 THEN
      OUTPUT "Pass"
   ELSE
      OUTPUT "Fail"
   ENDIF
ENDIF

CASE OF Choice
   1 : OUTPUT "Start"
   2 : OUTPUT "Help"
   OTHERWISE OUTPUT "Invalid"
ENDCASE

An IF inside another IF is nested. CASE is neater when one variable is compared with many fixed values.

8.1.6

Procedures and functions

  • a subroutine is a named block of code that can be called from anywhere in the program
  • a procedure does a task; a function does a task and returns a value
  • parameters pass values into the subroutine
  • benefits: code written once and reused, shorter programs, easier to test and maintain, work shared between programmers
PROCEDURE Greet(Name : STRING)
   OUTPUT "Hello ", Name
ENDPROCEDURE

FUNCTION Square(N : INTEGER) RETURNS INTEGER
   RETURN N * N
ENDFUNCTION

CALL Greet("Asha")
Area ← Square(5)
8.1.7

Local and global variables

  • a global variable is declared in the main program and can be used anywhere
  • a local variable is declared inside a subroutine and can only be used inside that subroutine; it disappears when the subroutine ends
  • local variables avoid accidental changes from other parts of the program and save memory
8.1.8

Library routines and maintainable programs

  • library routines are ready-made, tested subroutines supplied with the language: MOD, DIV, ROUND, RANDOM …
  • a maintainable program is easy for another programmer to understand and change:

8.2Programming

One name, many values

Instead of thirty variables for thirty marks, use one array with thirty elements. A 2D array is a table: rows and columns.

1

Understand

Two sections and a checklist

8.2.1

One-dimensional arrays

  • an array is a data structure that stores many values of the same data type under one identifier
  • each value is an element, found by its index; Cambridge pseudocode often starts at 1
DECLARE Names : ARRAY[1:30] OF STRING
Names[1] ← "Asha"
FOR Index ← 1 TO 30
   OUTPUT Names[Index]
NEXT Index
8.2.2

Two-dimensional arrays

  • a 2D array is like a table: Marks[row, column]
  • to process every element, use nested loops: an outer loop for the rows, an inner loop for the columns
DECLARE Marks : ARRAY[1:4, 1:3] OF INTEGER
FOR Row ← 1 TO 4
   FOR Col ← 1 TO 3
      INPUT Marks[Row, Col]
   NEXT Col
NEXT Row

8.3Programming

Data that survives when the program ends

Variables live in RAM and vanish when a program stops. Writing data to a file keeps it, ready to be read back next time.

1

Understand

Two sections and a checklist

8.3.1

Why use files?

  • data stored in a file is kept permanently (on secondary storage) after the program closes
  • it can be read again later, or by another program, and shared or backed up
8.3.2

Reading and writing files

OPENFILE "Students.txt" FOR WRITE     // starts a new, empty file
WRITEFILE "Students.txt", "Asha,15"
CLOSEFILE "Students.txt"

OPENFILE "Students.txt" FOR READ
WHILE NOT EOF("Students.txt") DO
   READFILE "Students.txt", Line
   OUTPUT Line
ENDWHILE
CLOSEFILE "Students.txt"
  • READ reads lines in order; WRITE creates a new file (overwriting any old one); APPEND adds to the end
  • EOF (end of file) is TRUE when there is nothing left to read
  • always CLOSE the file when finished
